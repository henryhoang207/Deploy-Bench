# H6 (confirmatory, as amended by D36): result on the registered minmax arm

Run: `python analysis/h6_analysis.py` -> `h6.json`. Data: `results/phase_2_conversion_app/conversion_sensitivity/`
(frozen plans, ledgers, selections, r01 sidecars, diagnostic scores). The percentile arm (DEV-1)
is exploratory and is not used.

| model | primary DV: smallest tested fp32 exclusion set within +1.0 pp | D36 prediction | r01 converter fallback (secondary) | D30 prediction (secondary) |
|---|---|---|---|---|
| AASIST | **none** (best K=48 of 327 ranked, +1.40 pp) | not evaluable | Abs, Div, Expand, MaxPool, ReduceMax, ReduceMean, Slice, Squeeze, Transpose, Unsqueeze | **not met**: ScatterND, TopK, Gather, GatherElements were quantized |
| AASIST-L | **none** (best K=48 of 313, +1.70 pp) | not evaluable | same list as AASIST | **not met**: same |
| RawNet2 | **K=16** (r09): 6 Conv incl. SincConv, 2 BN (first_bn, bn_before_gru), 2 GlobalAveragePool, 2 LeakyRelu, Selu, 2 Mul | **not met**: no GRU node in the set | GRU, Gather, MaxPool, Reshape, Squeeze, Transpose | met (GRU falls back) |
| Res-TSSDNet | **none** (best K=32 of 37, +2.90 pp) | not evaluable | Unsqueeze | met (conv/BN/ReLU quantized) |

**Verdict: H6 as amended is not supported.** Three of the four ranked models have no tested
configuration within the budget, so the D36 prediction cannot be evaluated for them. For the
one model where it can be evaluated (RawNet2), it is not met. The converter-coverage view
(secondary) also fails where it was most specific: ORT quantizes the graph-attention ops that
D30 predicted would fall back. It holds only for the GRU and for plain convolutions. Plain
convolutions being quantized did not make Res-TSSDNet usable: every Res-TSSDNet attempt flips
about 996 of the 2,000 diagnostic decisions at tau_eer.

**What the data do say (descriptive, within these five artifacts):** int8 damage under minmax
PTQ is not confined to the predicted op classes. RawNet2's minimal set is front-end and
normalisation layers (SincConv, first BN, the BN before the GRU), not the recurrence. For AASIST
and AASIST-L the highest-damage nodes are mixed (top 48: 23 / 28 in GAT modules, 6 in graph
pooling, the rest front-end/encoder), and 48 exclusions were not enough. This fits the named
uncontrolled factor (the shared raw-waveform front-end) at least as well as it fits op class.

**Disclosures.**
1. The D36 prediction for RawNet2 ("contains GRU nodes") could not have been met under this DV.
   ORT leaves GRU in fp32 by default, so a GRU node is never a candidate for exclusion. Claude
   drafted that restatement and flagged it at D36 as needing review before the tag; it was not
   revised. The failure is therefore partly one of design, and the paper must say so rather than
   present it as evidence against a mechanism.
2. Res-TSSDNet's arm is non-blind (D36).
3. "Graph-attention node" = the node name contains `GAT`. Graph pooling is reported separately.
4. Quantized vs fallback op lists come from `ptq.py`'s accounting: an op type is "quantized"
   if any instance has an input from DequantizeLinear. An op type can appear in both lists.
